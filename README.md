# 异步 FIFO（Async FIFO）

基于格雷码指针 + 两级同步器的跨时钟域 FIFO，深度可配置，用于 100MHz→37MHz 数据缓冲。

## 1. 设计规格
|   参数   |   值       |
|   ---    |   ---      |
| 数据位宽 | 8 bit      |
| 深度     | 16         |
| 写时钟   | 100 MHz    |
| 读时钟   | 37 MHz     |
| 资源开销 | XX 个寄存器 + 1 个双口 RAM |

## 2. 架构
（放一张架构图，或 ASCII 图）
   写时钟域                              读时钟域
   wptr(bin) →[bin2gray]→ wptr_gray →[两级同步]→ 判空
   rptr_gray ←[两级同步]← rptr(bin) ←[bin2gray]← rptr(bin)

## 3. 关键设计点
Ⅰ   **为什么用格雷码**：设计多bit二进制指针跨时钟域时，如果多位同时变化，接收端的采样器有可能会在翻转过程中的任何时刻采样，导致才到一个不存在的中间值；而格雷码再变化时，每次只有一位变化，采样出错也只在“采到新值”和“采到旧值”两者中的一个，表现为指针滞后一拍————导致假满或假空，不会损坏数据。
Ⅱ    **为什么深度必须 2 的幂**：标准格雷码只有在状态数为2时才能保证“首尾也只差1bit，如果深度是非2的幂，回绕处格雷码会多处跳变，导致上一条结论失效。
- **假空/假满**：同步延迟导致判断偏保守，牺牲带宽换取正确性……

## 6. 遇到的问题，产生的疑问
    1.最后判断空满的时候，不小心把编码方式搞混，产生了判断满状态是最高位不同，其余位相同的认知，忽略了格雷码和二进制判定不同，导致结果出错。这是由于格雷码每加2^n时，对应的格雷码会在最高位和次高位同时翻转，所以需要比较前两位。
